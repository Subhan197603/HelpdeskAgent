# Analyst copilot

Milestone 9, Task 9.1 adds a read-only analyst workspace endpoint:

```http
POST /api/v1/agent/tickets/{ticket_key}/copilot/analysis
```

The body may include an optional, bounded `focus` string. The response contains a PII-reduced
ticket summary, classified activity, authorized similar resolved tickets, approved internal
runbooks, release-filtered Oracle documentation, server-bound citations, an inference-labelled
technical recommendation, and the complete AI/retrieval version capture.

## Authorization and evidence

Only `AGENT`, `SUPPORT_MANAGER`, and `PLATFORM_ADMIN` roles receive `AI_ANALYST_USE`. The target
ticket is loaded through the normal analyst-ticket visibility check. Similar tickets are limited to
resolved or closed tickets in the same project and are filtered by support group unless the caller
has `TICKET_READ_ALL`.

Knowledge searches always use the `ANALYST` retrieval persona. Existing tenant, audience,
classification, principal, group, business-unit, and source ACLs apply in SQL. Runbook results must
be approved `RUNBOOK` documents. Oracle results must come from an approved
`ORACLE_PUBLIC_DOCUMENTATION` source and, when an environment release is configured, match its
exact release family and code.

## Safety behavior

- Reporter/requester names and identifiers are not sent in the summary.
- Activity retains `PUBLIC`, `INTERNAL`, or `SYSTEM` classification; actor identity is omitted from
  copilot output.
- Contact-shaped personal data is redacted from bounded activity and historical-resolution text.
- Prompt-instruction-shaped ticket or evidence content is excluded from provider context.
- Recommendations are labelled `INFERENCE` and are omitted if no authorized citation can be bound.
- Citation identifiers and metadata are generated by the server, not accepted from the model.
- The provider receives no tools. This endpoint cannot comment, assign, change priority, change
  status, resolve, close, or otherwise mutate a ticket.

## Required deployment configuration

Publish an approved AI configuration with:

- agent code `ANALYST_COPILOT`
- use case `TICKET_ANALYSIS`
- a published prompt, empty/read-only tool-set version, model-policy version, and retrieval-policy
  version
- an approved enabled feature policy and applicable budget/rate limits

If AI or authorized retrieval is unavailable, the API returns the standard fail-closed problem
response. Provider secrets are never stored in ticket, conversation, evidence, audit, or response
payloads.
